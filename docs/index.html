Inside Alpamayo‑R1

Abstract

What NVIDIA says it does

“We introduce Alpamayo 1, a vision–language–action model (VLA) that integrates Chain of Causation reasoning with trajectory planning to enhance decision‑making in complex driving scenarios.” — NVIDIA Research

Trained on 1,727 hours of driving (300,000+ clips across 25 countries), reported to reach state‑of‑the‑art results on reasoning, trajectory generation, alignment, safety and latency — via open‑loop metrics, closed‑loop simulation and real‑vehicle tests. The rest of this page is not that evaluation; it's what the released code does, read directly.

Worth knowing: the repo's own README describes the backbone as Cosmos‑Reason. The shipped checkpoint and base_model.py actually load Qwen/Qwen3‑VL‑8B‑Instruct (config.json: "vlm_backend": "qwenvl3"). Everything below describes what runs.
Method

One inference call, eight stages

AlpamayoR1.sample_trajectories_from_data_with_vlm_rollout() is the single method both test_inference.py and this fork's demo_video.py call. Step through it with the controls below — every stage you've seen stays visible.

1 / 8

Inputs

4 cameras × 4 history frames (16 images) plus 1.6s of ego motion, rotated into the ego‑local frame at t0.

→
2 / 8

Prompt

16 image tokens + 48 history‑placeholder tokens; the assistant turn is pre‑seeded so generation must continue it.

→
3 / 8

History tokens

16 steps × 3 dims of ego‑local motion delta‑encoded into 48 integers, scattered into the placeholder slots.

→
4 / 8

VLM reasoning (causal)

36‑layer Qwen3‑VL backbone encodes all frames and autoregressively writes Chain‑of‑Causation; trajectory tokens are logit‑masked out.

→
5 / 8

Cache handoff

The full prompt+reasoning KV‑cache is kept; new M‑RoPE ids and a mask are built for 64 future slots. Nothing is re‑encoded.

→
6 / 8

Diffusion expert (non‑causal)

A second, narrower 36‑layer transformer denoises 64 waypoints over 10 Euler steps, reading the cache layer‑for‑layer.

→
7 / 8

Action decode

Each waypoint's (acceleration, curvature) is forward‑integrated through a unicycle kinematic model into (x, y, heading).

→
8 / 8

Output

Text between ‹cot_start›/‹cot_end› plus the (x,y,heading) trajectory are returned — what demo_video.py renders.

The actual novelty

Two transformers, one shared cache

Not token‑level interleaving of text and numbers — a strict two‑phase rollout. It only works because both transformers have exactly 36 layers: layer i of the action expert reads the KV pairs layer i of the VLM produced.

Phase A — reasoning

  • Sees all 16 camera frames + 48 history tokens
  • Ordinary causal, autoregressive text decoding
  • Discrete trajectory‑token vocab (4,000 slots) exists but is logit‑masked — unused at inference
  • Ends the instant it emits <|traj_future_start|>

Phase B — denoising

  • Never sees a token id — only continuous per‑waypoint embeddings
  • Starts from Gaussian noise, 10 Euler steps to the final (accel, curvature) field
  • Re‑encodes nothing: reuses Phase A's cache directly
  • Optionally CUDA‑graph captured per input shape for repeated calls
Action space

A unicycle, not a point cloud of waypoints

The model never predicts (x, y) directly. It predicts acceleration and curvature at each of 64 steps; a closed‑form kinematic integrator turns that into a trajectory — so the output is always physically drivable.

// per waypoint, dt = 0.1s
v[t]  = cumsum(accel) · dt
θ[t]  = cumsum(curvature · v) · dt
x[t], y[t] = ∫ v·cosθ, v·sinθ
// below 0.6 m/s, curvature → 0
// (heading estimate is ill‑conditioned near standstill)
Acceleration bounds±9.8 m/s²
Curvature bounds±0.33 m⁻¹
Waypoints × dims64 × 2
Diffusion steps10 (Euler)
Discrete alt. encoding3,000 bins · unused
