Inside Alpamayo‑R1

A code‑grounded tour of NVIDIA's open vision‑language‑action model for autonomous driving — eight cameras in, a plain‑English reason and a 6.4‑second trajectory out.

Reverse‑engineered from src/alpamayo_r1/ for internal study · maintained at jundduck/alpamayo

Alpamayo‑R1 is an 11.1B‑parameter model that takes 4 calibrated cameras and 1.6 seconds of ego motion history, and in one forward pass produces a free‑text Chain‑of‑Causation explanation and a 64‑waypoint, 6.4‑second trajectory. This page walks through what the released code actually does, stage by stage — click through the pipeline below the way you would in the source.

Worth knowing: the repo's own README describes the backbone as Cosmos‑Reason. The shipped checkpoint and base_model.py actually load Qwen/Qwen3‑VL‑8B‑Instruct (config.json: "vlm_backend": "qwenvl3"). This page describes what runs, not what the table says.

The actual novelty

Two transformers, one shared cache

Not token‑level interleaving of text and numbers — a strict two‑phase rollout. It only works because both transformers have exactly 36 layers: layer i of the action expert reads the KV pairs layer i of the VLM produced.

Phase A — reasoning

  • Sees all 16 camera frames + 48 history tokens
  • Ordinary causal, autoregressive text decoding
  • Discrete trajectory‑token vocab (4,000 slots) exists but is logit‑masked — unused at inference
  • Ends the instant it emits <|traj_future_start|>

Phase B — denoising

  • Never sees a token id — only continuous per‑waypoint embeddings
  • Starts from Gaussian noise, 10 Euler steps to the final (accel, curvature) field
  • Re‑encodes nothing: reuses Phase A's cache directly
  • Optionally CUDA‑graph captured per input shape for repeated calls
Action space

A unicycle, not a point cloud of waypoints

The model never predicts (x, y) directly. It predicts acceleration and curvature at each of 64 steps; a closed‑form kinematic integrator turns that into a trajectory — so the output is always physically drivable.

// per waypoint, dt = 0.1s
v[t]  = cumsum(accel) · dt
θ[t]  = cumsum(curvature · v) · dt
x[t], y[t] = ∫ v·cosθ, v·sinθ
// below 0.6 m/s, curvature → 0
// (heading estimate is ill‑conditioned near standstill)
